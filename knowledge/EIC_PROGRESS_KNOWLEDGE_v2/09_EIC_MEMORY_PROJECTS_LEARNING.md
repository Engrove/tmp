# EIC Memory, Projects, Search and Learning

## Who owns what
- **Memory**: durable personal preferences, aliases, constraints and
  conventions that came from a human. Not project status, repo state, logs,
  credentials, raw conversations or transient counts.
- **Projects**: identity, scope and focus. **Updates**: chronology and
  checkpoints. **Milestones**: their own checkpoints. **Sharing owners**:
  visibility.
- **Semantic search and AIK pointers**: discovery only. Confirm current facts
  at the owner you found.
- **Global Skills**: reusable method. **Knowledge** (this package): method for
  autonomous Greenfield missions and stable rules.

## Projects
- For a known project read its record and relevant updates/milestones; use a
  targeted semantic search as a supplement when it helps.
- For GFW missions resolve the canonical registry/mission head; current_focus is
  a steering hint, not a fact owner.
- Record material decisions, stage completions, tests and hand-offs once at
  the correct owner. Do not create records to document an unchanged read.
- A Grundprojekt is private and is never shared. Do not create projects,
  missions or workers for bookkeeping.

## Memory writes
Retain only clear, stable, future-useful meaning from actual human input.
Before changing retained meaning, search active and historical records for the
same subject and supersede with links instead of duplicating.

## Learning (Self-learn, Kaizen, Operator Learning, AIK)
- Assessments run at keypoints: session start, stage DONE, rotation, yield or
  stop — not every turn. A lightweight assessment does not require a write.
- If a learning surface rejects access in this session, record it once and do
  not retry it in this session.
- Retired learning levels 0/1/2 stay retired.
- Explicit holds win: while a learning destination is held, record only a local
  `PAUSED_NO_EXPORT` decision. No policy update, test, timer, code fix,
  restart or generic "continue" lifts a hold.
- Company-model export follows 11_EIC_COMPANY_LEARNING_POLICY.md.

## Partial reads
Follow pagination and chunk continuation to the end you need. A partial page
is progress, not degradation, and not a blocker.
